Rutas públicas, privadas y por rol

Un administrador crea espacios y reservas. Un residente solo reserva. Quien no ha iniciado sesión solo ve el registro y el login. Hoy construimos esa regla en el frontend de Paseo App.

Los pasos van en el orden en que se escriben en clase. Cada uno dice qué archivo tocar, qué explicar y qué probar antes de seguir.

El concepto 15 min

Cada ruta de la app responde a una pregunta antes de mostrarse. Una pública no pregunta nada. Una privada pregunta «¿hay sesión?». Una por rol pregunta además «¿tu rol está en la lista?».

El flujo

Las guardias se anidan. Primero RutaPrivada revisa la sesión; solo si pasa, RutaPorRol revisa el rol. Si todo pasa, <Outlet /> pinta la página pedida.

1

Crear el contexto de sesión

src/contexto/ContextoSesion.jsx nuevo

Qué explicar: el login escribe la sesión, las guardias la leen y el menú la usa. En vez de pasar props por toda la app, la ponemos en un contexto. localStorage evita perderla al recargar. estaLogueado y esAdministrador son atajos para no repetir la comparación en cada componente.

import { createContext, useContext, useState } from 'react'

// 1. Creamos el contexto: una "caja" que cualquier componente puede abrir
const ContextoSesion = createContext(null)

const CLAVE = 'sesionPaseoApp'

// Lee la sesion guardada en el navegador (si recargo la pagina no se pierde)
function leerSesionGuardada() {
    try {
        const texto = localStorage.getItem(CLAVE)
        return texto ? JSON.parse(texto) : null
    } catch {
        return null
    }
}

// 2. El proveedor envuelve la app y guarda quien esta logueado
export function ProveedorSesion({ children }) {

    const [usuario, setUsuario] = useState(leerSesionGuardada)

    function guardarSesion(usuarioLogueado) {
        localStorage.setItem(CLAVE, JSON.stringify(usuarioLogueado))
        setUsuario(usuarioLogueado)
    }

    function cerrarSesion() {
        localStorage.removeItem(CLAVE)
        setUsuario(null)
    }

    // Lo que compartimos con toda la aplicacion
    const valor = {
        usuario,
        estaLogueado: usuario !== null,
        esAdministrador: usuario?.rol === 'ADMINISTRADOR',
        guardarSesion,
        cerrarSesion,
    }

    return (
        <ContextoSesion.Provider value={valor}>
            {children}
        </ContextoSesion.Provider>
    )
}

// 3. Hook para usar la sesion desde cualquier componente
export function useSesion() {
    return useContext(ContextoSesion)
}

Crear el servicio de login

src/services/servicioAuth.js nuevo

Qué explicar: el backend aún no tiene endpoint de login, así que buscamos el usuario por correo. Aislarlo en un servicio permite cambiar solo esta función cuando exista POST /usuarios/login. Deja claro que esto no valida la contraseña.

import { listarUsuarios } from './servicioUsuarios.js'

// OJO: el backend todavia no tiene un endpoint de login.
// Por ahora buscamos el usuario por correo en la lista de usuarios.
// Esto NO valida la contraseña (el API no la devuelve, y esta bien que no lo haga).
// Cuando exista POST /usuarios/login solo hay que cambiar esta funcion:
//
//   const respuesta = await clienteApi.post('/usuarios/login', { correo, contraseña })
//   return respuesta.data
//
export async function iniciarSesion(correo, contraseña) {
    const usuarios = await listarUsuarios()

    function tieneElMismoCorreo(usuario) {
        return usuario.correo.toLowerCase() === correo.toLowerCase()
    }

    const usuarioEncontrado = usuarios.find(tieneElMismoCorreo)

    if (!usuarioEncontrado) {
        throw new Error('Correo o contraseña incorrectos')
    }

    return usuarioEncontrado
}

4

Crear la página de login y su ruta

src/paginas/Login.jsx nuevo · src/App.jsx modificar

Qué explicar: el flujo es pedir el usuario al servicio, guardarlo con guardarSesion y navegar. El if (estaLogueado) del principio es la primera «guardia» que ven: si ya hay sesión, el login no se muestra.

import { useState } from 'react'
import { Link, Navigate, useNavigate } from 'react-router-dom'

import { iniciarSesion } from '../services/servicioAuth.js'
import { useSesion } from '../contexto/ContextoSesion.jsx'

import { PanelFormulario } from '../componentes/PanelFormulario'

const IMAGEN = 'https://images.unsplash.com/photo-1545324418-cc1a3fa10c00?w=1400&q=80'

export function Login() {
  const navegar = useNavigate()
  const { estaLogueado, guardarSesion } = useSesion()

  const [datos, setDatos] = useState({ correo: '', contraseña: '' })
  const [error, setError] = useState('')
  const [enviando, setEnviando] = useState(false)

  // Si ya hay sesion no tiene sentido ver el login
  if (estaLogueado) {
    return <Navigate to="/home" replace />
  }

  function manejarCambio(evento) {
    const { name, value } = evento.target
    setDatos({ ...datos, [name]: value })
  }

  async function manejarEnvio(evento) {
    evento.preventDefault()
    setError('')
    setEnviando(true)

    try {
      const usuario = await iniciarSesion(datos.correo, datos.contraseña)
      guardarSesion(usuario)
      navegar('/home')
    } catch (error) {
      setError(error.response?.data?.message || error.message || 'No fue posible iniciar sesión')
    } finally {
      setEnviando(false)
    }
  }

  return (
    <PanelFormulario
      imagen={IMAGEN}
      titulo="Tu unidad residencial, en un solo lugar"
      subtitulo="Reserva zonas comunes y administra los espacios de tu conjunto en Sabaneta."
    >
      <h2 className="fw-bold mb-1">Iniciar sesión</h2>
      <p className="text-muted mb-4">Ingresa para reservar o administrar espacios.</p>

      {error && <div className="alert alert-danger">{error}</div>}

      <form onSubmit={manejarEnvio}>
        <div className="mb-3">
          <label className="form-label fw-semibold">Correo</label>
          <div className="input-group">
            <span className="input-group-text"><i className="bi bi-envelope"></i></span>
            <input
              type="email"
              name="correo"
              placeholder="correo@ejemplo.com"
              className="form-control"
              value={datos.correo}
              onChange={manejarCambio}
              required
            />
          </div>
        </div>

        <div className="mb-4">
          <label className="form-label fw-semibold">Contraseña</label>
          <div className="input-group">
            <span className="input-group-text"><i className="bi bi-lock"></i></span>
            <input
              type="password"
              name="contraseña"
              className="form-control"
              value={datos.contraseña}
              onChange={manejarCambio}
              required
            />
          </div>
        </div>

        <button type="submit" className="btn btn-marca btn-lg w-100" disabled={enviando}>
          <i className="bi bi-box-arrow-in-right me-2"></i>
          {enviando ? 'Ingresando...' : 'Ingresar'}
        </button>
      </form>

      <p className="text-center text-muted mt-4 mb-0">
        ¿No tienes cuenta? <Link to="/">Regístrate</Link>
      </p>
    </PanelFormulario>
  )
}

Bloque 3 · Las guardias 25 min

Una guardia es un componente que elige entre dos salidas: <Navigate> para mandar al usuario a otro lado, o <Outlet /> para pintar la ruta hija que pidió.

6

Crear RutaPrivada

src/rutas/RutaPrivada.jsx nuevo

Qué explicar: <Outlet /> es el hueco donde React Router pinta la ruta hija. replace reemplaza la entrada del historial para que «atrás» no vuelva a la ruta protegida.

import { Navigate, Outlet } from 'react-router-dom'
import { useSesion } from '../contexto/ContextoSesion.jsx'

// Deja pasar solo a usuarios logueados.
// <Outlet /> pinta la ruta hija que el usuario pidio.
export function RutaPrivada() {
    const { estaLogueado } = useSesion()

    if (!estaLogueado) {
        return <Navigate to="/login" replace />
    }

    return <Outlet />
}

Proteger las rutas privadas

src/App.jsx modificar

Qué explicar: una <Route> sin path, solo con element, es una ruta de diseño. No cambia la URL; solo envuelve a sus hijas. Todo lo que pongas dentro pasa por la guardia.

import { RutaPrivada } from './rutas/RutaPrivada'

<Routes>
  {/* Rutas publicas: cualquiera puede entrar */}
  <Route path="/" element={<RegistroUsuario />} />
  <Route path="/login" element={<Login />} />

  {/* Rutas privadas: solo usuarios logueados */}
  <Route element={<RutaPrivada />}>

    <Route path="/reservas" element={<RegistroReserva />} />
    <Route path="/listaespacios" element={<ListaEspacios />} />

  </Route>
</Routes>

8

Crear RutaPorRol y proteger /espacios

src/rutas/RutaPorRol.jsx nuevo · src/App.jsx modificar

Qué explicar: recibe un arreglo de roles y no un solo rol, para que sirva en el futuro con combinaciones como ['ADMINISTRADOR', 'PORTERO']. Al anidarla dentro de RutaPrivada, primero se revisa la sesión y después el rol. Usa el simulador de arriba para mostrar el orden.

import { Navigate, Outlet } from 'react-router-dom'
import { useSesion } from '../contexto/ContextoSesion.jsx'

// Deja pasar solo si el rol del usuario esta en la lista de roles permitidos.
// Ejemplo: <RutaPorRol rolesPermitidos={['ADMINISTRADOR']} />
export function RutaPorRol({ rolesPermitidos }) {
    const { usuario } = useSesion()

    if (!usuario) {
        return <Navigate to="/login" replace />
    }

    if (!rolesPermitidos.includes(usuario.rol)) {
        return <Navigate to="/home" replace />
    }

    return <Outlet />
}

Mueve /espacios dentro de una nueva guardia. Así queda App.jsx completo:

import { BrowserRouter, Routes, Route, Navigate } from 'react-router-dom'
import { ProveedorSesion } from './contexto/ContextoSesion'
import { RutaPrivada } from './rutas/RutaPrivada'
import { RutaPorRol } from './rutas/RutaPorRol'
import { RegistroUsuario } from './paginas/RegistroUsuario'
import { Login } from './paginas/Login'
import { Home } from './paginas/Home'
import { RegistroEspacio } from './paginas/RegistroEspacio'
import { RegistroReserva } from './paginas/RegistroReserva'
import {ListaEspacios} from './paginas/ListaEspacios'

export function App() {
  return (
    <ProveedorSesion>
      <BrowserRouter>
        <Routes>
          {/* Rutas publicas: cualquiera puede entrar */}
          <Route path="/" element={<RegistroUsuario />} />
          <Route path="/login" element={<Login />} />

          {/* Rutas privadas: solo usuarios logueados */}
          <Route element={<RutaPrivada />}>
            <Route path="/home" element={<Home />} />
            <Route path="/reservas" element={<RegistroReserva />} />
            <Route path="/listaespacios" element={<ListaEspacios />} />

            {/* Rutas por rol: solo ADMINISTRADOR */}
            <Route element={<RutaPorRol rolesPermitidos={['ADMINISTRADOR']} />}>
              <Route path="/espacios" element={<RegistroEspacio />} />
            </Route>
          </Route>

          {/* Cualquier otra ruta */}
          <Route path="*" element={<Navigate to="/login" replace />} />
        </Routes>
      </BrowserRouter>
    </ProveedorSesion>
  )
}

9

Ocultar lo que no puedes usar y cerrar sesión

src/paginas/Home.jsx modificar

Qué explicar: si el residente ve el botón «Espacios» y al hacer clic lo devuelven a inicio, parece un error. Por eso lo ocultamos. Pero ocultar no es proteger: lo que impide entrar escribiendo la URL es la guardia, y hacen falta las dos cosas. «Salir» deja de ser un Link y pasa a ser un botón que borra la sesión.

import { Link, useNavigate } from 'react-router-dom'
import { useSesion } from '../contexto/ContextoSesion.jsx'

// dentro del componente
const navegar = useNavigate()
const { usuario, esAdministrador, cerrarSesion } = useSesion()

function salir() {
  cerrarSesion()
  navegar('/login')
}

// en el navbar
<span className="text-white-50 small d-none d-md-inline me-2">
  <i className="bi bi-person-circle me-1"></i>{usuario.nombres} · {usuario.rol}
</span>
{esAdministrador && (
  <Link to="/espacios" className="btn btn-outline-light btn-sm">
    <i className="bi bi-door-open me-1"></i>Espacios
  </Link>
)}
<button type="button" onClick={salir} className="btn btn-light btn-sm">
  <i className="bi bi-box-arrow-right me-1"></i>Salir
</button>

// haz lo mismo con el boton "Registrar espacio" de la portada
// y con la tarjeta "Registrar espacio": envuelvelos en {esAdministrador && ( ... )}
Prueba

Como USUARIO ves tu nombre y rol, pero no ves «Espacios» ni «Registrar espacio». Como ADMINISTRADOR sí los ves. «Salir» te lleva a /login, y si después escribes /home, no entras.

La seguridad real vive en el backend

Todo lo que hicimos corre en el navegador del usuario. Cualquiera puede abrir las DevTools, editar localStorage y cambiar su rol a ADMINISTRADOR. El menú le mostraría el botón y la guardia lo dejaría pasar.

Pruébalo en clase

DevTools → Application → Local Storage → sesionPaseoApp. Cambia "rol":"USUARIO" por "rol":"ADMINISTRADOR" y recarga. Ahora entras a /espacios.

Por eso el API también debe validar: quién eres (autenticación) y si puedes hacer esa acción (autorización). Los pasos que siguen en paseoGlobant:

  1. Un endpoint de login que compare la contraseña y devuelva el usuario, idealmente con un token (JWT).
  2. Que POST /espacios rechace con 403 a quien no sea administrador.
  3. Guardar la contraseña cifrada (por ejemplo con BCrypt), nunca en texto plano.

Un primer login en Spring

// UsuarioControlador.java
@PostMapping("/login")
public ResponseEntity<UsuarioDTO> controlarLogin(@RequestBody Usuario datos) {
    return ResponseEntity.ok(this.servicio.iniciarSesion(datos.getCorreo(), datos.getContraseña()));
}

// UsuarioServicioImpl.java
@Override
public UsuarioDTO iniciarSesion(String correo, String contraseña) {
    Usuario usuario = this.repositorioUsuario.findByCorreo(correo)
            .orElseThrow(() -> new ResponseStatusException(HttpStatus.UNAUTHORIZED, "Correo o contraseña incorrectos"));

    if (!usuario.getContraseña().equals(contraseña)) {
        throw new ResponseStatusException(HttpStatus.UNAUTHORIZED, "Correo o contraseña incorrectos");
    }
    return this.mapaUsuario.convertir_modelo_a_dto(usuario);
}

Con eso, en el frontend solo cambia iniciarSesion en servicioAuth.js. Las guardias, el contexto y el menú quedan iguales.

Para ver los mensajes de error del API

Spring Boot no envía el texto de ResponseStatusException por defecto: message llega vacío. Agrega server.error.include-message=always en application.properties y el frontend mostrará «Ya existe un usuario con el correo ingresado».

Cierre

  1. Recarga la página con la sesión abierta: sigues logueado gracias a localStorage.
  2. Como USUARIO, edita en DevTools "rol":"USUARIO" por "rol":"ADMINISTRADOR" y recarga. Ahora entras a /espacios.
  3. Discute con la clase por qué eso demuestra que el frontend no da seguridad y que el backend debe validar cada petición. Esto conecta con la sección «Seguridad real».

Reto para los estudiantes

Crear la ruta /usuarios con ListaUsuarios, visible solo para el administrador, y mostrar en el menú un enlace hacia ella solo si esAdministrador es verdadero.
